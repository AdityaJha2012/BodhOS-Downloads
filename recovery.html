Recover safely

Start with separate backups. Rescue diagnostics can inspect the system without administrator access.

  1. Open Bodh Rescue and choose Diagnose boot and storage. Read its results and save the diagnostic log.
  2. Use Back up files to choose the source and a different destination. Check available space. A backup destination must not be inside its source.
  3. Boot repair needs administrator authorization and the correct mounted Linux root. An EFI installation also needs its EFI system partition mounted. Use the same BIOS or UEFI mode as the installed system.
  4. Use Timeshift to restore an available system snapshot. System snapshots do not replace separate backups of student projects.

Repair writes to the selected installation. Have an administrator check the target disk and boot mode before proceeding. A failed operation must be investigated rather than repeated blindly.

Accounts and projects

Persistent student accounts keep Projects. Classroom sessions are temporary. Account removal must preserve student projects. The existing local administrator is the recovery route for local parental settings.

Updates

Use the maintained Debian APT sources and Bodh update tools. Confirm snapshot storage is available before a protected update. No production Bodh OTA endpoint or cloud account login is enabled in this release.
