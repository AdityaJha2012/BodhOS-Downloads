BODH OS · SCHOOL LAB GUIDE

Install. Set up. Start learning.

A persistent desktop for students, with separate temporary Classroom sessions.

Development preview. Use a disposable virtual machine first. Physical hardware and school deployment require separate checks. ARM and Raspberry Pi images are not covered by this x86_64 guide.

Install on a real PC?

Follow the USB and real PC guide. Back up first and test the live desktop before installing.

1. Check your image

Keep the ISO and its matching .sha256 file together. In PowerShell, run Get-FileHash .\BodhOS-PC-0.3.0-preview.38-amd64.iso -Algorithm SHA256. Compare the full result with the checksum file. A different result means the image must not be used.

2. Create a fresh VirtualBox machine

  1. Select a Linux Debian 64 bit guest. Skip VirtualBox unattended installation so you can use the Bodh installer.
  2. For an initial evaluation, allocate two virtual CPUs, 4 GB RAM and a new 32 GB virtual disk. These are test settings, not a certified minimum. Later compare 2 GB and 4 GB using the published measurements.
  3. Select VMSVGA graphics, disable 3D acceleration and choose USB Tablet as the pointing device. Use NAT networking.
  4. Attach the verified ISO to the optical drive. Choose BIOS or enable EFI deliberately. Keep Secure Boot off for this evaluation. Test the other firmware mode in a separate VM.

3. Install onto the new virtual disk

  1. Start the VM. The live desktop is temporary. To retain projects after shutdown, choose an installation entry from the boot menu.
  2. Choose your language, region, keyboard and time zone. Let the wired network configure automatically if available.
  3. Give the computer a distinct name, such as bodh-lab-01. Leave Domain name blank unless your school IT team supplies one. This is not a website registration step.
  4. Leave the separate root password blank. Then create your own normal account and password. That first account can administer the computer through sudo. There is no universal installed administrator password.
  5. Select the new empty virtual disk. Guided partitioning can erase the selected disk. Never select a physical disk containing needed data.
  6. Complete installation and bootloader setup. Eject the ISO when prompted, then restart from the installed virtual disk.
Simpler setup is in development. A new offline profile will skip domain, mirror and separate root password questions. It is not in the current Preview 0.38 ISO. The steps above describe the existing download.

4. Configure the school

  1. Open Bodh Settings → School setup. Enter the school name and persistent logins such as student-alex. Apply the configuration and set each new account's password.
  2. Configure networking through Network connections. Choose a Timeshift snapshot drive before enabling update protection.
  3. Enroll required USB devices separately, with the keyboard, mouse and other needed devices connected. Do this on each actual machine.
  4. Use Standard effects first. Reduced disables compositing. Glass is not offered.
  5. Optional storage quotas require an already configured quota filesystem. A limit of 0 preserves existing limits. Confirm enforcement before using quotas in a lab.

5. Confirm student work is safe

Sign in to a persistent student account. Open Coding Apps, edit a starter in its editor and run it. Save in ~/Projects, restart and check that the edit remains.

In Bodh Settings → Student files, back up the project to a separate mounted destination. Verify the backup and restore a copy into a new folder. Backups are not encrypted, so use a private school approved location. A second folder on the same disk does not protect against disk failure.

Classroom is a different, temporary account. Its files clear after logout. Do not use it for projects that need to be kept.

School shares and optional management

Connect to an authenticated school share in the file manager, for example smb://server/share. Choose its mounted folder when backing up projects. Preview 0.35 includes the filesystem bridge needed by the backup tools. Confirm the school's access permissions and test restoration before relying on a share.

Remote management stays disabled until an administrator explicitly enrolls an account and SSH key. Ansible runs on the administrator computer. Students do not need an Ansible agent, and administrator authorization remains required. Follow the instructions from your school administrator to review enrollment, host verification, network restrictions and revocation.

Before a school pilot

Test the actual computers, network, USB storage, printers and audio devices. Confirm updates, recovery, backup destinations and student data retention with school staff. VM results alone do not establish school readiness.
